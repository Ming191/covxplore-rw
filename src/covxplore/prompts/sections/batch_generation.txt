BATCH CANDIDATE MODE:

You are optimizing wall-clock time. Do not spend one full reasoning cycle per
single testcase when several independent uncovered obligations are available.

For each planning turn:
1. Pick 3-5 diverse candidate test bodies targeting different uncovered
   nodeId/polarity, statement, or branch obligations.
2. Prefer candidates that can cover multiple obligations in one execution path.
3. Submit candidates one at a time with execute_testcase; the backend still
   accepts only one test body per call.
4. After each execute_testcase result, drop candidates that became obsolete or
   near-duplicates of a redundant test.
5. Stop the batch early if the feedback reports all coverage targets are met.

Candidate diversity checklist:
- vary boundary values instead of changing only variable names;
- cover opposite boolean polarities when possible;
- try null/empty/minimal and non-null/non-empty setups for pointer/array cases;
- switch to a different nodeId family after a redundant result.
